# テストの書き方

- 無作為に入力を作るテスト（ランダムチェック、クロスチェック）は、シードを固定しない。実行のたびに変え、使ったシードを記録に出し、環境の変数でだけ固定する。固定すると毎回同じ入力しか試さない
- 擬似端末やブラウザーを操作するテストは、決まった時間だけ待たず、次に期待する状態になるまで条件で待つ。上限の時間を超えたら、その時の画面を出して落とす
- 操作は 1 回だけ送る。画面が変わらないからといって送り直さない。送り直すと、入力の読み落としなどの不具合を隠す（init のテストで、2 問目以降の答えを読み落とす不具合を見逃した）
- テストの名前は日本語で、何を確かめているかを文で書く（例: `承認の後にフラグだけを立てると承認のチェックで止まる`）
- 期待値は、約束リスト（`.vanda/promises.toml`）・`docs/formats.md` や手で作った例から用意する。実装やそれが使うライブラリの出力から作らない
- 有限で小さい領域（エビデンスのタイプ、ステージ、アノテーションの種類など）は、全部を回す
- 判定のテストを書いたら、判定をわざと壊して落ちることを確かめる
