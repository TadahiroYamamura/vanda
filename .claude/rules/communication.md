# やりとりの仕方

## 役割と、誰に聞くか

| 役割 | 受け持つこと |
|---|---|
| PO | 何を作るか、仕様、依存、プッシュを決める |
| 監督 | 計画を書き、開発者とテスト担当に渡し、成果を確かめて PO に報告する |
| 開発者 | 実装 |
| テスト担当 | テスト |

- 開発者とテスト担当は、計画にない判断が要るとき、作る前に監督に聞く。PO に直接は聞かない
- 監督は、PO が決めることを、自分で決めずに PO に聞く。監督が自分で決めたことは、報告で「監督が決めた」と分かるように書く

## 聞き方

- 1 回に聞くのは 1 つだけ。ほかにも聞くことがあれば、残りの数を添える
- 選択肢を表にし、推奨を先頭に置いて「（推奨）」と書く。推奨の理由を 1 行で添える
- 前の答えで決まることを、改めて聞かない

## 報告の仕方（開発者・テスト担当から監督へ）

報告には、次のものを、この順に書く。当てはまらないものは省く。

1. 結論（できたか、止めたか）
2. コミットのハッシュと subject
3. 確かめたこと（動かしたコマンドと結果。数えたものは数で）
4. 確かめていないこと（流していないテスト、試していない場合）
5. 計画から外れたこと
6. 決めてほしいこと（上の「聞き方」の形で）
7. pitfalls の候補（`.claude/rules/pitfalls.md` の 3 つを添える。なければ「ありません」）
8. 後片付け（起動したプロセス、一時のリポジトリが残っていないか）

- 確かめていないことを、確かめたように書かない
- 自分のテストや実装の誤りを直したときは、何を誤っていたかも書く
