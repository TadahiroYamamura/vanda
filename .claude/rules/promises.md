# 約束リストに書くもの

約束リスト（`.vanda/promises.toml`）は、間違いを検出するためにある。作業の成果は、約束とそのエビデンスで判断される。間違いの検出に役立たない約束は、PO が読む量と、保守の手間を増やすだけなので書かない。書き方の手順は、スキル promise-writing にある。

この規則の言葉と、約束リストの書き方の対応は次のとおり。

| 言葉 | 約束リストの書き方 |
|---|---|
| 用語 | `[[term]]` |
| 機能 | `[[feature]]` |
| 約束 | `[[claim]]` |
| エビデンス | `[[claim.evidence]]` |

## 正しさ

約束は、次の 3 つの正しさのどれか 1 つ以上に属する。

| 正しさ | 中身 |
|---|---|
| 規範的 | 外から課された決まりに従っている（法令、セキュリティ、プロトコルの仕様、明文化された業務ルール、他社との契約、外との取り決め） |
| 機能的 | 不変条件が守られ、想定した入力に対して想定どおりの出力が出る |
| 目的的 | 使いやすい、理解しやすい、役に立つ、期待を裏切らない。人の評価が要ることが多い |

## 約束にするもの・しないもの

- 約束にするのは、正しさのどれかに属し、反証できるものだけ。正しいかを確かめられない約束には意味がない
- 約束は、受け入れ基準の粒度で書く。正しさを実現する手段（並びの順、番号、件数の出し方、文言など）は約束にせず、コードとテストに置く（例: 「一覧に通し番号を振る」ではなく「PO はすべての約束を漏れなく閲覧し、承認するかフィードバックできる」）
- テストに書いた振る舞いは、そのテストがエビデンスとして支える約束の一部として守る
- 関知しないこと（どちらでもよいこと）は書かない
- 振る舞いを足す・変える作業では、その振る舞いが支える約束があるかを確かめる。なければ、約束を足すかを監督に聞く

## 反証の条件

- 文だけでは破れた状態が読み取れない約束（主に目的的正しさ）には、大まかな反証の条件を書く
- エビデンスには、具体的な反証の条件（テストが確かめること、数値のしきい値、レビューで見る点）を必ず書く。テストを書く側が通しやすい条件を自分で決めないよう、約束の文と大まかな反証の条件に答える形にする

## 機能

- 機能とは約束を実現するために実装するもの（どの正しさの約束でもよい）
- 実現する約束を言えないもの、ほかの機能の部品（画面の部品、表示の細部）は、機能にしない
