# Git の使い方

いつも守る決まり（`main` への操作は承認が要る、作者を `git -c` で指定しない、`gh` のトークン）は `.claude/rules/git.md` にある。

## ブランチ

| ブランチ | 名前 | 作る人 |
|---|---|---|
| ストーリーの作業ブランチ | `story-<番号>/main`（番号は GitHub の Issue の番号） | メインのエージェント |
| サブエージェントのブランチ | `story-<番号>/<役割>-<seq>`（例: `story-4/dev-1`、`story-4/test-2`、`story-4/audit-1`） | サブエージェント（名前はメインのエージェントが決めて渡す） |

- ストーリーのブランチは、すべて `story-<番号>/` の下に置く。まとめて探したり消したりできる（`git branch --list 'story-4/*'`）
- seq は、同じストーリー・同じ役割のブランチの中で重ならない番号にする。同時に動くエージェントが同じ番号を選ばないよう、メインのエージェントが決めてプロンプトで渡す
- サブエージェントは、ブランチごとに別の worktree で作業する

## コミット

- 作業ブランチとサブエージェントのブランチには、各エージェントが自分の判断でコミットしてよい
- メッセージは日本語で、`(type) subject` の形にする。type は `feat`・`fix`・`test`・`docs`・`refactor`・`chore`。subject は「〜を追加する」「〜を修正する」の形
- メッセージには、事実だけを書く。誤りに気づいたら直す（作業ブランチでは書き換えてよい）
- 目的の違う変更は、コミットを分ける
- ストーリーのトレーラー（`Story: <ID>`）は CLAUDE.md の「Git」に従う

## 取り込みとプッシュ

- サブエージェントのコミットは、メインのエージェントが差分を読んで確かめてから、作業ブランチに取り込む（`cherry-pick` か `merge`）
- 作業ブランチのプッシュは、メインのエージェントが各コミットを確かめたうえで判断し、行う。サブエージェントはプッシュしない
- 確かめること: 差分が報告と合うか、メッセージに事実と違うことがないか、トレーラーの形（`git interpret-trailers --parse`）

## 片付け

- 取り込んだサブエージェントのブランチと worktree は、メインのエージェントが消す（`git worktree remove`、`git branch -D`）
- Agent ツールの worktree が自動で作る `worktree-agent-<ID>` のブランチも、同じときに消す
