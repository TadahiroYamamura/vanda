# vanda 段 4 の 6 の直しの計画: 直訳調の言葉を、ふだん使う言い方にそろえる

story #4。PO の指摘で、英語を一語ずつ直訳した言い方（prompt を「問いかけ」など）をやめ、日本の開発者がふだん使う言い方（定着したカタカナ語・漢語を含む）にそろえる。PO は、用語（約束リストの `[[term]]`）の名前も変えると決めた（「承認」と「合意」、「チェック」と「審査」の使い方がぶれていたため）。振る舞いは変えない。ID（`agreement`・`check` など）、API の JSON の項目名、ファイル名（`agreements.toml` など）、CLI のコマンド名、審査の名前（`agreement`・`evidence-present` など設定に書く名前）は変えない。

## 用語・機能の名前（PO の決定。監督が約束リストを直す）

| 今 | 後 |
|---|---|
| 合意・合意する・合意済 | 承認・承認する・承認済 |
| 合意の記録 | 承認の記録 |
| 外れた合意 | 失効した承認 |
| 審査・審査を行う | チェック・チェックする |
| ○○の審査（用語の名前） | ○○のチェック |
| 範囲（審査の） | スコープ |
| 組込みのアダプタ | 組み込みのアダプタ |
| 指紋 | フィンガープリント |
| 由来 | 変更履歴 |
| 分岐点 | マージベース |
| 版 | バージョン |

- 用語 story-origin-check「由来の審査」は、変更履歴（約束の履歴）とは別の意味（コミットがどのストーリーのものか）なので、「コミットのストーリーのチェック」にする（監督の決定）

- 出す・示す・見せる・動かす・並べる・断る・求める・中身などの、ふつうの日本語は変えない
- 置き換えて文がつながらなくなる所は、意味を変えずに文を直す
- 「待ち受ける」はそのまま

## 担当と順

1. 監督（と、監督が任せる約束リストの書き手）: 約束リストの用語・機能の名前と、地の文
2. 開発者: CLI の出力・画面・API の誤りの文・コメント・`docs/formats.md`・`docs/spec.md`。CLI と画面の文言の「前 → 後」の一覧を報告に書く。1 と同じ表で置き換える
3. テスト担当: 2 の後。テストの名前・期待値・台本・`spec/` のコメント
4. 監督: CLAUDE.md・`.claude/rules/`・スキル。約束リストの文の中のかぎかっこの文言（画面や CLI にそのまま出すもの）と、2 の出力の文言が合っているかを確かめる

## 確かめること

- `nix develop -c make check`
- 上の表の「今」の言い方が、`docs/plans/` と、git の履歴・合意の記録を除いて残っていないこと（grep の結果を報告に書く）

## 禁止

- `pkill`・`killall`、`vanda init`、プッシュ、`git rebase`・`commit --amend`・`reset --hard`、`git switch` でほかのブランチに移ること
- 127.0.0.1:45569 と 127.0.0.1:45600 に触れること
- `docs/pitfalls.jsonl` の編集（候補は報告に書く）。合意の記録（`.vanda/agreements.toml`）の編集
- 開発者がテストのファイルを、テスト担当が実装のファイルを書き換えること。開発者とテスト担当が約束リストを書き換えること
