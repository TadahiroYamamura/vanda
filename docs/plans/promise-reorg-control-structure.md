# 約束リストの作り直し: vanda の制御図の草案

PO が直すためのたたき台。vanda を使った開発で、誰が、誰に、何を指示し、何が戻ってくるかを表にした。ガイドワード（`promise-reorg-guidewords.md`）を当てる対象の一覧として使う。約束リストはまだ変えない。

- 範囲は「vanda を使った開発」。vanda の外にあるもの（CI、マージ、ストーリーストア）も、損失につながるので入れた
- 「vanda の外」の列が「外」の行は、vanda が約束できない。前提として書くか、関知しないかを決める対象になる
- 人の呼び方（PO、開発者、使い始める人、外の人）は、約束リストの用語にまだない

## 1. 人と道具

| 名前 | 中身 |
|---|---|
| PO | 約束を読み、承認するかを決める人 |
| 開発者 | 約束リスト・コード・テストを書く人と AI のエージェント（テスト担当を含む） |
| 使い始める人 | リポジトリに vanda を入れ、設定する人 |
| 外の人 | カスタムアダプタを作る人 |
| CI | プッシュのたびに、テストと vanda check を動かすもの |
| vanda check | チェックを順に動かし、終了コードと出力を返す命令 |
| vanda サーバー | レビューの画面と API を出すもの |
| アダプタ | アノテーションかストーリーを読み、vanda に答えるもの |
| リポジトリ | git のリポジトリ。約束リスト、承認の記録、設定、コード、テストを持つ |
| ストーリーストア | ストーリーを持つ外のサービス |

## 3. 境界を越えるもの

規範的な損失のガイドワードを当てる対象。

| # | 越えるもの | どこから、どこへ |
|---|---|---|
| a | ブラウザーからのリクエスト | ブラウザー（ほかのサイトのページを含む）から vanda サーバーへ |
| b | ストーリーストアのトークン | vanda サーバーからストーリーストアへ |
| c | ストーリーの題・本文・添付 | ストーリーストアからレビューの画面へ |
| d | アダプタの答え | カスタムアダプタ（リポジトリの中のプログラム）から vanda へ |
| e | 承認の記録 | 承認した人の PC から、リポジトリを通して CI へ |
| f | 承認する人の名前 | git の設定から承認の記録へ |

## 4. 人としたいこと

目的的な損失のガイドワードを当てる対象。

| # | 人 | したいこと |
|---|---|---|
| A | PO | ソースコードを読まずに、ストーリーで変わったことが正しいかを判断する |
| B | PO | 承認したものが、後から黙って変わっていないと信じる |
| C | 開発者 | 何が足りなくてチェックが通らないかを知り、直す |
| D | 使い始める人 | 手で直さずに、vanda を使い始める |
| E | 外の人 | 組み込みのアダプタにない言語・ストーリーストアを vanda につなぐ |

## 6. 入れなかったもの

- vanda のビルドと配布（使っている vanda が、約束を満たした vanda と同じものか）
- git と、リポジトリを置くサービスの正しさ
- 開発者（AI のエージェント）への指示の出し方（計画、規則、スキル）
- 複数の PO がいる時の、PO の間の分担

## 7. 書きながら気づいた所

- 8 番: チェックの設定と CI の設定を書き換えれば、チェックを弱められる。チェックの設定が承認の対象のファイルになっているか、CI の設定を誰が守るかは、まだ確かめていない
- 9 番と 10 番: テストを動かすのは CI で、vanda check とは別の手順になっている。vanda check がテストの結果（通ったか）を見ているかは、まだ確かめていない。見ていないなら、エビデンスが「ある」ことと「通った」ことをつなぐのは CI の設定だけになる
- 11 番: チェックが失敗した時にマージを止めるのは、vanda の外の設定。vanda が約束できるのは終了コードまで
