# vanda init のテストの計画（テスト担当向け）

この計画は、`vanda init`（CMD-11）のテストを書くテスト担当のエージェントに渡す。テスト担当は、実装のコードを書き換えない。実装を読んで期待値を作らない。

前提として読むもの: `CLAUDE.md`、`docs/spec.md` の CMD-11、`docs/formats.md`、`docs/plans/init-impl.md` の「作るもの」。

## テストの決まり

段 2 と同じ。一時的な git のリポジトリは、テストごとの一時ディレクトリに作る。

## 道具

`vanda init` は端末でないと止まるので、問いかけのテストは、擬似端末（pty）で `vanda` を動かし、問いを読んで答えを書く。擬似端末を作るのに `github.com/creack/pty` を使う（テストだけで使う。PO が了承した）。問いかけは `charmbracelet/huh` なので、矢印キー・スペース・Enter の入力を送る。端末でないときに止まることのテストは、testscript で書く。

## 確かめること

| 確かめること |
|---|
| 既定の答えのまま進めると、読み取った値（ベースブランチ、GitHub のリポジトリ、見つかった言語）で 4 つのファイルができる。作った設定で `vanda doctor` が通る（GitHub Issues を選んだときは、設定の `api_url` を偽のサーバーにして確かめる）。`vanda check .vanda/checks/ci.toml --base <ベースブランチ> --story <ID>` が通る（作った直後のブランチには、ストーリーの ID のあるコミットがないため `--story` で渡す。渡さなければ、ストーリーが分からない旨で止まるのが正しい） |
| remote の URL の形（https、ssh、ssh の別名のホスト、GitHub でないホスト、remote なし）ごとに、問い 2（選んだ状態）・3 の既定の答えが決まる（全部を回す） |
| ストーリーの置き場所の選択肢（GitHub Issues・外部のコマンド・使わない）の全部で、問い 3・4 の出方と既定（GitHub Issues なら `#[0-9]+`、ほかは既定なし）と、書かれる `[story]` が合う |
| 言語（Go・シナリオ・TLA+・SQL）のあるなしの組み合わせ（16 通り）で、問いに出る言語と書かれる `[[annotation]]` が合う |
| 答えを変えると、その値で書かれる（ベースブランチ、リポジトリ、コマンド、ID の書き方、読むファイルのパターン） |
| 言語を選ぶ問いで、見つかった言語が選ばれた状態から始まり、そのまま進めると見つかった言語が書かれる。見つからなかった言語を選ぶと、それも書かれる。選びを外すと書かれない |
| ファイルのない（初期化した直後の）リポジトリでも、言語を選んで `[[annotation]]` を書ける。1 つも選ばなければ、案内に `[[annotation]]` を書くことと外部のコマンドのアダプタのことが出る |
| 形に合わない答え（選択肢にない番号、正規表現の誤り、空の文字列に当たる正規表現、既定のない ID の書き方を空にする、リポジトリの形）は、理由が出て同じ問いに戻る |
| 設定に `[[layer]]` が書かれず、案内に `[[layer]]` を書くことが出る |
| 作る前の確かめで n と答えると、何も作られない |
| 途中で入力を終える（Ctrl+D）と、何も作られない |
| 止める場合（端末でない、git の中でない、`.vanda/` がある）は、何も書かれず、理由が標準エラーに出て、終了コードが 1 |
| 作ったファイルにコメントがない |
| 審査の設定に、今ある審査が全部入っている |
