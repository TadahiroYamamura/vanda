# vanda init の実装の計画（開発者向け）

この計画は、`vanda init`（CMD-11）を実装する開発者のエージェントに渡す。テストの計画（`docs/plans/init-test.md`）は、別のテスト担当のエージェントに渡す。

前提として読むもの: `CLAUDE.md`、`docs/spec.md` の CMD-11、`docs/formats.md` の「設定」「約束リスト」「合意の記録」「審査の設定」。

## 作るもの

`vanda init` を、リポジトリの中（git の作業ツリーの中）で動かすと、端末で問いかけ、答えでリポジトリの一番上に `.vanda/` を作る。

### 止める場合（何も書かない）

| 場合 | 出すこと |
|---|---|
| 標準入力か標準出力が端末でない | 端末で動かすよう伝える |
| git の作業ツリーの中でない | git のリポジトリの中で動かすよう伝える |
| `.vanda/` がすでにある（ファイルでもディレクトリでも） | すでにあるので何も書き換えないと伝える |
| 問いかけの途中で入力が終わった（Ctrl+D）か、中断した（Ctrl+C） | 何も作らなかったと伝える |

端末かどうかは、標準ライブラリで確かめる（`os.File.Stat()` の `ModeCharDevice`）。依存を足さない。

### 問いかけ（この順）

既定の答えは `[ ]` の中に出し、空のまま Enter で既定を使う。答えが形に合わなければ、理由を出して同じ問いを聞き直す。

| # | 問い | 既定の答え（読み取り） | 書く所 |
|---|---|---|---|
| 1 | ベースブランチ | `origin/HEAD` が指すブランチ（例: `origin/main`）。なければ今のブランチ | `[gui]` の `base` |
| 2 | ストーリーの置き場所。番号を振った選択肢から選ぶ: GitHub Issues・外部のコマンド・使わない | remote `origin` が GitHub なら GitHub Issues、そうでなければ使わない | `[story]` の `adapter` か `command` |
| 3 | （2 が GitHub Issues のとき）リポジトリ（`<owner>/<repo>`）。（2 が外部のコマンドのとき）コマンドと引数 | GitHub Issues: remote `origin` の URL から読む（https と ssh の両方の形。ssh の別名のホスト（`github.com_xxx` など）も GitHub とみなす）。外部のコマンド: なし | `[story]` の `repository` か `command` |
| 4 | ストーリーの ID の書き方（正規表現） | 2 で選んだアダプタが持つ既定（GitHub Issues なら `#[0-9]+`。外部のコマンドと使わないは既定を持たないので、答えが要る） | `[story]` の `id_pattern` |
| 5 | 見つかった言語ごとに、アノテーションを読むか（y/n）と、読むファイルのパターン | 下の表 | `[[annotation]]` |
| 6 | 書く内容の一覧を出し、作るか（y/n） | y | — |

- 選択肢は、ストーリーの置き場所のアダプタを足したときに増やせるよう、アダプタの一覧から作る。ID の書き方の既定も、アダプタが持つ
- レイヤーは問いかけない。作った後の案内で、`.vanda/config.toml` に `[[layer]]` を書くよう伝える

問い 5 の言語の見つけ方と既定のパターン（git が追っているファイルで見る）:

| 言語 | 見つけ方 | 既定のパターン | アダプタ |
|---|---|---|---|
| Go | `*_test.go` がある | `**/*_test.go` | `go` |
| シナリオ | `*.txtar` がある | `**/*.txtar` | `txtar` |
| TLA+ | `*.tla` がある | `**/*.tla` | `tla` |
| SQL | `*.sql` がある | `**/*.sql` | `sql` |

### 作るファイル（値だけ。コメントは入れない）

| ファイル | 中身 |
|---|---|
| `.vanda/config.toml` | `version`（動いている vanda の版）、`[[annotation]]`、`[story]`、`[gui]`。`[[layer]]` は書かない。`promises`・`agreements` は既定のままなので書かない |
| `.vanda/promises.toml` | 空 |
| `.vanda/agreements.toml` | 空 |
| `.vanda/checks/ci.toml` | 今ある審査を全部、`docs/formats.md` の「審査の種類」の順に、範囲は審査ごとに決まったもの（ストーリーで変わったものを見る審査は `story`） |

- 作った後に、`vanda doctor` と同じ確かめ（設定が読めるか）を行い、作ったファイルの一覧と、次にすること（`.vanda/config.toml` に `[[layer]]` を書く、`vanda check .vanda/checks/ci.toml --base <ベースブランチ>` を CI に足す）を出す
- コミットはしない
- 文言は CLAUDE.md の「文言」に従う

## 依存

足さない（端末かどうかの確かめは標準ライブラリで行う）。

## 進め方

段 2 と同じ。小さくコミットし、監督に報告する。計画にない判断は作る前に聞く。プッシュはしない。
