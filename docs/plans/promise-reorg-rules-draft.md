# 約束リスト

約束リスト（`.vanda/promises.toml`）は、間違いを検出するためにある。作業の成果は、仕様とそのエビデンスで判断される。

約束リストは仕様書ではない。細かい修正のたびに書き換える使い方はしない。約束リストを書く・直す時は、スキル promise-writing に従う。

## 項目

約束リストに書くものを、まとめて「項目」と呼ぶ。

| 言葉 | 約束リストの書き方 | 中身 |
|---|---|---|
| 性質 | `[[property]]` | ソフトウェアが満たすべき性質。提供すべき価値と、セキュリティなどの守るべき決まり |
| 機能 | `[[feature]]` | 性質を実現するために実装するもの |
| 仕様 | `[[spec]]` | 機能が満たすべき事前条件・事後条件・不変条件・制約・受け入れ条件 |
| エビデンス | `[[spec.evidence]]` | 仕様が支持されている証拠 |
| 用語 | `[[term]]` | ユビキタス言語の定義 |
| 前提 | `[[truth]]` | 用語・性質・仕様の前提となる事実。検証されない |

性質・機能・仕様・エビデンスは、抽象から具体へ並ぶ 4 つの層。用語と前提は、4 つの層を横断する。

## 作業の中で守ること

- テストに書いた振る舞いは、そのテストがエビデンスとして支持する仕様の一部として守る
- 約束リストに書かない細部（並び、件数のしきい値、文言など）の正は、テストに置く。テストにない振る舞いは、いつでも変わりうる。変わっては困る振る舞いは、テストに書く
- テストの確かめる中身を変えた・消した時は、報告に独立した項目で並べる。細部を確かめるのは開発者（人）で、ソースコードではなく、テストがどう変更されたかを見て確かめるため
- 振る舞いを足す・変える作業では、その振る舞いが支持する仕様があるかを確かめる。なければ、仕様を足すかを質問する
- 十分性（上の層の項目が、下の層の項目により抜け漏れなく具体化されていること）を確認したと記録するのは、人だけ。開発者（AI）が行うのは、確認の材料を作ることまで
