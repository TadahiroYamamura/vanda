# 約束リストの作り直し: 答責性の構成要素と作り方の草案

PO が書いた草案。約束リストの作り直しの案（`promise-reorg-upper-claims.md`）を評価するための物差しにする。約束リストと規則はまだ変えない。

## 1. 正しさの種類と、損なわれると起きること

| 正しさ | 損なわれると起きること |
|---|---|
| 目的的 | 使う人の課題が解決されない |
| 機能的 | 出力や記録が壊れたり、間違っていたりする |
| 規範的 | ルールや法律に違反する、第三者に損失が発生する |

## 2. 約束の重要度を評価する方法

- 違反の発生から気づくまでの期間
- 損失の程度
- 被害を受ける人
- 復旧までの時間（または復旧できるか）

## 3. 答責性の構成要素

| 構成要素 | 定義 |
|---|---|
| 完全性 | 守るべき約束がすべて列挙されている |
| 十分性 | 上位の約束は下位の約束により抜け漏れなく具体化されている |
| 反証可能性 | 約束が破れた状態を判別できる |
| 証跡性 | 約束が今守られていることを、破れていれば得られないエビデンスで客観的に証明できる |
| 追跡可能性 | 判断の経緯や検証の結果が履歴として残る |
| 真正性 | 保存された記録や証拠が作成された当時のまま改ざん・消去されておらず、記録された人が本当にその人である |
| 独立性 | コードを書く主体と、正しさを確認する主体が独立している。主体には、期待値の源（仕様や手計算など）を含む |

## 4. 答責性の作り方

STAMP/STPA の手法を使い、完全性・十分性のある約束リストを得る。その後 vanda の機能を使い、残りの構成要素を作っていく。

| 手順 | 得るもの |
|---|---|
| 損失とハザードを定義する（ガイドワードを使う。`promise-reorg-guidewords.md`） | 完全性・十分性 |
| STAMP の制御図を描く | 十分性 |
| 害のある指示を洗い出す | 大まかな反証の条件、受け入れ基準 |

制御図とガイドワードで得られる十分性は、図に描いたものについてだけ。できるだけ抜けのない結果を得るために、分け方の軸を決めて MECE に考える。

## 5. vanda が役に立っているかを評価する方針

| 観点 | 問い |
|---|---|
| 品質 | 承認され、チェックも通ったのに、後から見つかった欠陥がどれだけあるか |
| 実装速度 | コードを書いて機能をリリースするまでの時間が短くなっているか |
| メンテの容易さ | 約束リストを保守するコストが、AI が出力したコードをレビューするコストを下回っているか |
| 経済性 | 「注意力」という、人が持つ限られた資源を有効に使えているか。ストーリー 1 件で PO が読む約束の数と、承認のうちフィードバックが付いた割合で数える（数え方は案） |
